# MNIST Handwritten Digit Classification using TensorFlow/Keras

A small, reproducible deep-learning project that classifies handwritten digits
(0-9) from the **MNIST** dataset using **TensorFlow/Keras**, together with one
controlled experiment that measures whether adding a **Dropout** layer actually
helps.

The project contains a guided Jupyter notebook, an equivalent one-command
training script, a written report, and the code that generates every figure and
metric that appears in them.

> **Every number in this repository is produced by running the code.**
> No accuracy, loss, timing or confusion-matrix value is hard-coded or
> estimated. `results/metrics.json` is written by the run, and
> `report/MNIST_Report.md` is filled in from that same file.

## Requirements

- Python 3.9 or newer
- The packages listed in `requirements.txt` (TensorFlow, NumPy, Matplotlib,
  pandas, scikit-learn, Jupyter)

Version pins are given as *lower bounds* rather than exact versions on purpose:
the correct TensorFlow build depends on your Python version and platform. To
freeze the exact environment that produced your own results, run
`pip freeze > requirements-lock.txt` after installing.

## How to run

**Option A - the script (fastest, fully automatic):**

```bash
python src/train_model.py
```

This trains both models, prints the metrics, writes every figure to `results/`,
saves the best model to `models/mnist_model.keras`, writes `results/metrics.json`
and then rewrites `report/MNIST_Report.md` with the measured numbers.

**Option B - the notebook (guided, good for submitting / demonstrating):**

```bash
jupyter notebook mnist_digit_classification.ipynb
```

Then choose **Kernel -> Restart Kernel and Run All Cells**. The notebook follows
the same steps, displays each figure inline and writes the same output files.

Training both models for 10 epochs takes only a few minutes on a normal CPU.

## What the code does

1. **Load** MNIST with `tf.keras.datasets.mnist.load_data()` - the standard
   dataset, loaded exactly as the assignment requires.
2. **Explore** the data: shapes, number of classes, pixel range, class counts
   and a visual sample of each digit.
3. **Preprocess** by scaling pixel values from 0-255 to 0.0-1.0. The test set is
   never used for training or model selection.
4. **Baseline model:** a small fully-connected network.

   ```text
   Input 28x28 -> Flatten (784) -> Dense 128 + ReLU -> Dense 10 + Softmax
   ```

5. **Experiment - adding Dropout:** the identical network with one change, a
   `Dropout(0.5)` layer after the hidden layer. Same optimiser, loss, epochs,
   batch size and validation split, and the random seed is reset before each
   model is built so both start from the same weights. This is what makes the
   comparison fair rather than suggestive.
6. **Evaluate** both models once on the untouched test set, producing the
   accuracy, loss, confusion matrix and per-class report.
7. **Save** the better-performing model and write the report.

### Conclusion policy

The project does **not** assume that Dropout helps. The conclusion text in both
the notebook and the report is generated from the measured difference between
the two models:

- if the difference is smaller than 0.1 percentage points, the two models are
  reported as performing essentially the same (a single run cannot distinguish
  them);
- otherwise the text states plainly whether Dropout improved or reduced
  accuracy, by how much, and what that does and does not justify.

## Reproducibility

- All random seeds (Python, NumPy, TensorFlow) are fixed to `42`.
- Both models share identical settings; only the Dropout layer differs.
- The script has no hard-coded results - the report template only contains
  `{{PLACEHOLDER}}` tokens that the run replaces with measured values.
- `results/metrics.json` records the versions used, so a run is traceable.

Note that results will still vary slightly between machines and between
TensorFlow versions, and a single training run is not enough to prove that one
architecture is reliably better. Reporting the measured difference honestly is
the point of the experiment.
